# 历史访谈与决策树

状态：历史记录。后续用户明确改为平台和生成应用均采用 LocalStorage、无平台账号及后端数据库、生成单个 HTML，定时任务只在页面打开时运行。以下旧方案不再作为当前交付要求；当前规范见 requirements.md 和 delivery-plan.md。

最终方案见 [delivery-plan.md](delivery-plan.md)，逐项验收见 [acceptance.md](acceptance.md)。本文件保留需求与访谈决策记录。

## 已明确的要求

- 交付真实可用、具备上线条件的 Web 应用。
- 参考 https://atoms-demo.pub.atoms.world 的功能与效果，不要求完全一致。
- 登录和注册账号，上线后任何人均可注册。
- 接入多家大模型厂商 API。
- 一句话描述需求，AI 实时生成完整可运行的代码，支持部署。
- 通过对话迭代；每个版本自动存档，可回滚、导出。
- 普通构建模式，以及 Plan and Execute 模式。
- 创建文件夹并统一管理对话。
- 深度研究：网上查找资料，整理为调研文档。
- 简洁、现代、清新柔和的界面，避免多余装饰。
- Python 后端。
- 用户数据与账号关联并在云端持久化，登录后更换浏览器仍可访问历史数据。此项取代初始的仅浏览器本地存储要求；浏览器可作为缓存，不能是唯一数据来源。
- 用户填写自己的模型 API Key，模型调用费用由用户对应的厂商账户承担。
- 首版支持生成包含后端、数据库、用户系统的完整应用。
- 构建工作由开发代理承担；产品负责人全程知情并保有最终决定权。
- Demo 必须具备真实交互、数据持久化和实际可用的功能，提供可测试的在线访问链接。
- 时间与资源允许时尽量覆盖初始化、注册和核心使用流程，以及至少一个延展能力；不能以纯静态展示或仅概念验证代替可用产品。
- 文件夹内可以组织多条对话，交互参考 GPT 网页端的项目组织方式。
- 普通模式直接构建并预览；Plan and Execute 先展示可修改计划，用户确认后执行。任务可停止，构建错误自动尝试修复，重试次数有限。
- 首版由平台托管生成应用，点击发布获得独立访问链接。
- 回滚主要用于应用构建期间；应用投入使用后应保留业务数据。
- 首版模型厂商：OpenAI、Anthropic、DeepSeek、通义千问、Kimi；支持自定义 API 地址和模型名称。Gemini 不列入已确认的首版名单。
- 模型凭证由服务端加密保存，用户换浏览器登录后继续可用，支持替换与删除。
- 深度研究可独立执行并导出报告，后续构建可以参考报告。
- 每条构建对话拥有独立应用与版本；文件夹仅组织多条对话，研究报告可供其他对话引用。
- 只使用一套数据库，取消预览库与正式库分离的建议，尽量简化实现。
- 关闭页面后构建与研究继续在后台执行。
- 平台和生成应用采用统一、简单的技术栈。
- 构建完成后的工作台可切换代码查看与直接预览。
- 对话界面提供历史记录入口，点击后弹出版本历史弹窗；每轮对话产生新代码即形成新版本。
- 项目页以卡片展示已构建应用，提供“全部/已收藏”、打开、克隆、复制链接、取消发布和删除等操作；隐私控制已按用户最新决定移除。
- 克隆当前选中版本的源码与非敏感配置，创建独立应用及新对话；不包含原聊天记录、业务数据、应用用户账号、密钥或发布链接，副本默认未发布。
- 删除经确认后下线应用，将项目及对应对话移入可恢复回收站；永久删除再次确认并清除关联数据。取消发布仅停止对外访问，保留项目和数据。
- 增加属于当前对话的定时 AI 自动化设置；到点在同一对话中执行只读检查与汇报，可使用有权访问的网页、搜索、文档/数据读取工具，不在生成应用中写调度器，不自动改代码或发布。
- 定时配置包括任务名称、具体工作、频率与执行时间、时区及通知偏好；卡片支持编辑、暂停、恢复、删除和执行历史。已有记录不影响后续控制，取消后不能再产生执行。

## 决策树

### 第一轮：已处理

- Q1：开放注册，不以小范围邀请作为首版范围。
- Q2：跨浏览器访问用户历史数据，采用云端持久化。
- Q3：完整应用生成，包含后端、数据库和用户系统；不收缩为仅前端生成。
- Q4：用户自带 API Key。
- Q5：地域与预算不作为当前需求访谈的门槛，暂不设置预算数字，也未授权具体付费采购。开发代理负责提出具体方案，涉及实际费用时交用户决定。

“共享订单的商城”只是上一轮访谈中开发代理举的能力边界示例，不属于用户需求，也不是验收范围。

### 第二轮：已处理

- Q6：一个项目文件夹可以放多条对话；具体应用归属在 Q13 中确定。
- Q7：接受普通模式直接构建预览、计划模式确认后执行，以及停止和有限自动修复。
- Q8：首版平台托管，点击发布获得独立链接。
- Q9：构建期可回滚，投入使用后保留业务数据。
- Q10：OpenAI、Anthropic、DeepSeek、通义千问、Kimi，以及自定义 API 地址和模型名称。
- Q11：服务端加密保存模型凭证，支持跨浏览器继续使用、替换和删除。
- Q12：独立研究并导出报告，后续构建可引用。

### 第三轮：已处理

- Q13：接受文件夹组织多条对话，每条构建对话有独立应用和版本，研究报告可供其他对话引用。
- Q14：用户选择一套数据库，拒绝维护预览、正式两套数据库的建议。最终方案明确：同一生成应用的预览与发布共用业务数据，不因发布或代码回滚复制、清空数据；库内仍需隔离不同用户和应用的访问权限。该行为进入最终整体确认。
- Q15：后台继续执行，重开页面或换浏览器登录可以查看任务进度与结果。
- Q16：接受统一技术栈，要求尽量简单；具体实现方案供最终整体确认。
- 补充：代码和预览可切换，历史记录以弹窗呈现，每轮生成新代码形成新版本。

### 开发代理负责提出的实现基线

以下进入最终方案供用户整体审阅，不要求用户逐一选择底层工具；尚未实施。

- 平台账号注册、登录、退出、用户数据隔离；生成应用的账号系统与平台账号分开。
- 流式展示任务阶段与日志，模型调用失败给出真实错误；自动修复有上限，失败不会覆盖上一成功版本。
- 每轮产生新代码后存档完整代码快照与构建状态；只有运行验证成功的版本才替换当前可用预览。源码导出包含依赖清单、运行说明和环境变量示例，不包含模型凭证与业务数据。
- 应用代码在独立运行环境执行，不在平台 API 进程中直接执行；平台数据与生成应用的数据分离。
- 研究真实检索网络资料，报告包含来源链接与引用；检索失败时明确说明，不能伪造已检索结果。具体检索服务与上线依赖由开发代理核实。
- 发布由用户触发；拟采用固定应用链接，更新预览后需再次发布才影响线上版本。任务与发布失败均须可见、可重试。
- 公开注册、私有工作区；是否公开源代码不由“发布应用”自动推导。

### 第四轮：项目页新增行为，已答复

- Q17：复制当前选中版本的源码和非敏感配置，创建独立应用与新对话；不包含原有聊天记录，不复制原应用业务数据、用户账号、密钥和发布链接，副本默认未发布。
- Q18：用户选择取消隐私控制功能，移除项目菜单对应入口；平台账号权限与私有工作区隔离仍是基础实现要求。
- Q19：接受确认后下线并移入回收站、支持恢复、永久删除再次确认并清除关联数据；取消发布只停止对外访问，保留项目和数据。

上述为已明确需求；新增字段、菜单、收藏与回收站状态需服务端持久化并遵守用户隔离。

### 第五轮：定时任务范围，已答复

- Q20：用户明确为当前 Chat 的自动化设置，在原对话定时检查和汇报。先前“定时构建”的建议被用户的只读边界取代，不能自动修改代码或发布。
- 任务使用该对话可用且已获权限的网页、搜索、文档/数据读取能力。汇报留在原对话，不创建代码版本。
- 配置项、编辑/暂停/恢复/删除与历史保留行为已明确，后端必须实际阻止暂停/删除后的触发。
- Q21：同一条回复存在两组时间描述：前段每小时至每年、默认浏览器时区；末段单次/每天/每周、默认北京时间。不能静默将其中一组视为已确认。

### 第六轮：时间规则、通知与异常处理，已答复

- Q21：每小时、每天、每周、每月、每年；默认创建时浏览器时区，取不到回退 Asia/Shanghai，允许手动修改。最新清单不包含单次任务。
- Q22：站内通知即可。
- Q23：接受同一任务不重叠、失败记录不自动反复重试、平台故障最多补最近一次、主动暂停恢复不补跑。

具体方案还列出了配置修订使未启动旧任务失效、暂停/删除终止未完成执行、对话回收站暂停关联计划等可审阅基线，随完整方案确认。
