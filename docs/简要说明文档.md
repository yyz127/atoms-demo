# Atmos 项目简要说明

## 实现思路与取舍

开发流程：先用 grill-with-docs 梳理需求并生成需求文档，开发第一版；之后按模块分别开启多个 Agent 对话完成新增需求的开发，以保证各模块的上下文完整，主对话的上下文无污染。最后部署上线并修复问题：Bug也开新对话处理，简单且相似的问题可合并修复。

Atmos 是一个通过对话生成应用的工作台：React 负责交互和预览，Python 负责模型调用、研究检索和账号接口。用户配置自己的模型和 API Key，调用费用由用户承担。

生成结果统一为单个 HTML，便于预览、下载和分享；代价是生成的应用没有独立后端，业务数据只保存在使用者的浏览器中。预览运行在隔离的 iframe 中，避免生成代码直接读取平台数据。

游客工作空间保存在本地；登录用户的平台记录可同步到PostgreSQL云数据库，模型 Key 在服务端加密保存。免费部署优先控制成本，暂不提供生成应用的公开托管。

## 当前完成程度

- **主链路：**1、输入需求后流式展示生成内容，完成后在 iframe 中预览；可通过多轮对话继续迭代。切换为计划模式后，先确认计划再构建应用。2、支持深度研究，先生成研究计划，再生成调研文档。并且调研文档可直接构建为应用。
- **版本管理：**每轮生成保存版本，可查看或恢复旧版本，并以恢复的版本继续修改；预览数据保留。
**项目管理页面：**卡片展示应用，支持搜索、收藏、打开、克隆、重命名、移动文件夹和移入回收站。
**研究报告汇总页面：**集中展示报告，支持查看、导出 Markdown 和基于报告构建应用。
- **会话与界面：**侧栏展示最近对话，支持文件夹、重命名和回收站；项目页支持搜索。工作台提供对话、预览和代码查看，游客记录保存在本地，账号工作空间可同步云端。
- **导出与研究：**可下载带预览数据或空模板的HTML；深度研究支持编辑并确认计划、检索来源和导出报告。
- **部署与验证：**部署至 [Render 在线地址](https://atmos-demo-9uuv.onrender.com)。DeepSeek 已真实验证生成、迭代和研究；前端构建、自动化测试及浏览器功能检查也有通过记录。

## 平台
- React Web 工作台通过 Python 认证与数据接口使用一套 PostgreSQL；账号、对话、文件夹、版本、研究、模型配置、运行记录及通知按用户隔离并跨浏览器读取。
- 支持邮箱密码注册及登录；密码只保存加盐哈希，旧账号须使用已登录会话设置密码；服务端加密保存模型 Key，不能向浏览器返回已有明文。
- 游客工作空间独立保存在本地；旧记录迁移须先预览和确认，不自动覆盖云端。生成应用的业务数据仍仅存访问者浏览器。
- 对接 OpenAI、Anthropic、DeepSeek、通义千问、Kimi，以及自定义 HTTPS API 地址和模型名称；用户提供自己的 API Key。
- 普通模式直接生成并预览；Plan and Execute 模式先生成可编辑计划，确认后执行。支持停止、真实错误提示、最多 3 次自动修复。
- 每轮产生新代码形成版本，保留历史并支持恢复；代码回滚不重置预览数据。
- 文件夹组织多条对话，每条构建对话拥有独立应用与版本。研究报告可以供其他对话引用。

## 生成应用

- 自然语言生成的产物统一是一个 HTML 文件，内联 CSS 和 JavaScript。
- 生成应用无账号、无后端数据库，业务记录通过 LocalStorage 保存。
- 工作台可切换代码与真实预览，历史记录以弹窗展示。
- 一键下载当前选中版本 HTML，可选带预览数据或空模板；导出文件可以独立打开，不带平台模型密钥和聊天记录。
- 项目页提供应用卡片、全部/已收藏、打开、克隆、复制链接、取消发布、删除，不提供隐私控制开关。
- 克隆仅复制当前选中版本源码与非敏感配置，创建独立应用和空的新对话；不带原聊天、历史、业务数据、应用用户、密钥或发布链接，默认未发布。
- 删除前确认并下线，项目及对应对话进入可恢复回收站；永久删除再次确认。取消发布仅停止公开访问，保留本地项目和数据。

## 研究与发布

- 真实搜索并读取公开网页，报告带来源与局限，支持 Markdown 导出和用于后续构建。
- 平台最终部署到 Render，并交付经过验证的在线访问链接。
- 用户允许将发布的 HTML 及可选预览数据上传托管空间；聊天、密钥、历史版本不进入公开产物。访问者后续操作保存于各自浏览器。
- 固定发布链接指向显式发布版本；新版本须再次发布才更新，取消发布即停止访问。
- 用户已选择首版免费部署平台，暂不启用公开应用托管。默认 render.yaml 不创建磁盘或付费资源；发布按钮与接口禁用，HTML 导出保留。
- 长期公开托管作为后续能力保留实现，需要另行决定资源方案。免费 Web Service 和账号方案已部署；当前不发送验证邮件。


## 后续投入与优先级

1. **先保证可用和数据安全：**确定数据库到期后的持续使用和备份方案。优先级中。
2. **补齐真实场景验收：**逐步验证主要模型厂商、线上检索和生成应用的常见交互，记录失败原因。优先级中。
3. **改善生成质量：**支持生成带前后端的应用，不止是html。优先级高，可优先完成。
4. **按需求扩展：** 多 Agent 分工。优先级高。
